# TGaiBot — Telegram-аккаунт с ИИ

Юзербот отвечает от обычного Telegram-аккаунта через Telethon/MTProto. Основная модель — **Claude Sonnet 5.5** (`claude-sonnet-5-5`) через A6 API. Озвучка — Fish Audio `s2.1-pro-free`, выбранный голос настроен в локальном `.env`. Генерация изображений — **GPT Image 2.5 Flare** (`gpt-image-2.5-flare`) через тот же A6 API.

В текущем окружении зависимости установлены, API модели, изображений и озвучки проверены. Не хватает только Telegram API ID/hash и интерактивного входа в аккаунт. Для включения экспериментальных звонков дополнительно нужен список разрешённых собеседников. BotFather-токен не используется.

## Запуск на этом компьютере.

1. Получите свои `api_id` и `api_hash` в [Telegram API development tools](https://my.telegram.org/apps). Заполните `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` в локальном `.env`. Ключи A6/Fish уже сохранены — повторно вводить их не нужно.
2. Выполните в PowerShell:

```powershell
cd C:\Projects\TGaiBot
.\.venv\Scripts\python.exe -m tgaibot doctor
.\.venv\Scripts\python.exe -m tgaibot login
.\.venv\Scripts\python.exe -m tgaibot run
```

`login` запрашивает номер с кодом страны, код Telegram и при необходимости пароль 2FA. Ввод скрыт; вводите их **только в локальном интерактивном терминале**. Они не записываются в `.env` или журнал. Авторизованная сессия сохраняется в `data/telegram.session`. Повторный запуск `run` использует её. Также доступны `login.ps1` и `run.ps1`.

Приложение отвечает, пока процесс работает и компьютер подключён к интернету. Ctrl+C останавливает его. Для постоянной работы подготовлен Docker-образ и конфигурация Railway; порядок запуска ниже. Одновременный запуск двух процессов в одном хранилище блокируется. Не запускайте одну сессию одновременно локально и на сервере.

## Railway: запуск владельцем один раз

1. Выполните локальный `login`, затем `python -m tgaibot export-session`. Секрет появится в `data/railway-session.env`, а не в консоли. До запуска сервера остановите локальный `run`.
2. В Railway создайте проект из этого GitHub-репозитория. Dockerfile уже содержит Python, FFmpeg, русский шрифт, распознавание речи и зависимости экспериментальных звонков. Для работы помощника домен не нужен; для просмотра личного архива включите домен Railway и задайте пароль, как описано ниже.
3. **Подключите Volume к `/data`**. Здесь хранятся память, файлы и загруженная модель Whisper. Без volume они пропадут при пересоздании контейнера. Держите одну реплику и не включайте автоматическое засыпание сервиса.
4. В Variables перенесите из локального `.env` значения `MODEL_API_KEY`, `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `FISH_API_KEY`; из экспортированного файла — `TELEGRAM_SESSION`. Добавьте `MODEL_NAME=claude-sonnet-5-5`, `FISH_MODEL=s2.1-pro-free`, `FISH_REFERENCE_ID=41d6b093e3014fb097a0b3eb1749247c`, `VOICE_REPLIES=auto`, `ENABLE_TRANSCRIPTION=true`, `DATA_DIR=/data`. При необходимости заполните `ALLOWED_USER_IDS` ID девушки.
5. Для личного архива задайте `ARCHIVE_PASSWORD` — отдельный пароль длиной от 16 символов — и включите публичный HTTPS-домен Railway для сервиса. Приложение использует выданный Railway `PORT`. Сам архив и файлы доступны только после входа по паролю; не используйте пароль от Telegram.
6. Запустите Deploy. При первом аудиосообщении Whisper скачает модель в постоянное хранилище; первая расшифровка может занять больше времени. Если серверу не хватает памяти для `base`, можно выбрать `WHISPER_MODEL=tiny`, учитывая снижение точности.

`railway.json` задаёт одну реплику, отсутствие перекрытия развёртываний и до пяти перезапусков после ошибки. Сессии и ключи не включаются ни в Git, ни в Docker build context. Для проверки образа локально: `docker build -t tgaibot:local .`. Реальный вход в Telegram и первый ответ нужно проверить после настройки переменных; сборка образа сама по себе не означает, что аккаунт запущен.

Основания конфигурации: [Railway Dockerfiles](https://docs.railway.com/guides/dockerfiles), [Volumes](https://docs.railway.com/volumes), [Config as Code](https://docs.railway.com/config-as-code/reference).

## Действия по обычной просьбе

Можно написать «Сделай PDF с планом поездки», «Сделай Excel с расходами», «Сохрани это в Markdown-файл», «Найди в интернете…», «Найди место на карте и пришли точку». Голосовые просьбы проходят через ту же цепочку после распознавания. Для точной расшифровки добавьте подпись «Расшифруй дословно»; Whisper может ошибаться, особенно в именах и числах.

Модель вызывает разрешённые инструменты через function calling. PDF, XLSX, TXT, MD, CSV и JSON создаются настоящими файлами и отправляются только в текущий чат. Для PDF доступны кириллица, заголовки, абзацы и код; это текстовый документ без встроенных изображений. Excel получает оформленную шапку, фильтры, закреплённую строку и несколько листов. Значения сохраняются как числа или текст; формулы не исполняются. Лимиты: 40000 символов в текстовом документе, до 8 листов / 30 столбцов / 1000 строк, суммарно 15000 ячеек в Excel. Созданные файлы сохраняются вместе с вложениями и удаляются при очистке памяти.

Интернет-поиск по умолчанию работает через DDGS без дополнительного ключа. Он возвращает до пяти ссылок с фрагментами, а не полные страницы; публичные поисковики могут ограничивать запросы. Для отдельного поискового API предусмотрен `TAVILY_API_KEY`. Ошибка поиска не подменяется выдуманной выдачей.

Просьба «фотку покажи» вызывает `send_web_photo`: поиск изображений Bing/DuckDuckGo, загрузку доступного оригинала (либо превью), проверку соответствия запросу моделью и отправку фото в этот же чат со ссылкой на источник. Генерация для этого не используется. Проверяются до трёх результатов; если подходящее фото недоступно, помощник сообщает об этом. Проверка моделью не гарантирует подлинность найденной фотографии. Загрузка ограничена 8 МБ, поддерживает JPEG/PNG/WebP; локальные адреса, приватные DNS-ответы и перенаправления во внутреннюю сеть запрещены. Токены проверки входят в стоимость модели, отправленные фото считаются отдельно от платной генерации в `/stats` и веб-админке.

При ответе на конкретное сообщение Telegram в контекст передаётся до 4000 символов его текста, даже если оно вышло из свежей памяти. Цитата используется для понимания предмета просьбы, её команды не исполняются. Цитаты из других диалогов не загружаются. Если исходное сообщение удалено или недоступно, это явно отмечается. Медиа из цитаты автоматически не распознаётся повторно.

Поиск мест использует Photon на данных OpenStreetMap, с общей паузой между запросами и кешем. Геоточку можно отправить только из результатов поиска текущего запроса. Поиск по названию может дать неоднозначные совпадения; модель должна проверить название/город и при необходимости уточнить. Это не сервис бронирований, маршрутов или проверки часов работы. Присланная пользователем геолокация также распознаётся. Условия публичного сервиса и отсутствие гарантии доступности описаны в [Photon](https://github.com/komoot/photon#demo-server).

На один запрос разрешены до восьми инструментов и пяти шагов модели. Повтор одинакового действия в одном запросе не отправляет файл повторно. Инструменты не исполняют код модели, не имеют доступа к произвольным локальным путям и не отправляют материалы посторонним людям. Поиск получает поисковую фразу, карты — название места; содержимое результатов считается данными, а не инструкциями.

## Фоновые задачи

Можно написать «В фоне сравни варианты поездки и сделай PDF» и продолжить обычную переписку. Помощник сохраняет поручение, составляет план, использует поиск, карты и создание файлов, затем присылает итог в тот же чат. Для сложного поручения модель также может сама выбрать фоновое выполнение. Если не хватает сведений, задача ждёт уточнения: ответьте, например, «Для задачи 3: выезжаем из Алматы, бюджет 100 тысяч».

Управление обычными фразами:

- «Что сделано?» или «Мои задачи» — последние 12 задач с состоянием и кратким итогом.
- «Статус задачи 3» — план, текущий шаг, подтверждённые действия и результат.
- «Отмени задачу 3» — остановить работу. Уже отправленные файлы остаются в чате.
- «Через час подготовь список покупок и пришли его» — одноразовое отложенное поручение, максимум на семь дней. Время показывается в UTC+05:00. Повторяющееся расписание пока не поддерживается.

План и выполненные действия показаны отдельно. Состояния: в очереди, выполняется, готово, нужно уточнение, отменена, не удалось завершить или нужна проверка отправки. Список и статус доступны без обращения к модели и не ждут завершения фоновой задачи. У каждого собеседника свои задачи; чужие переписки и задания ИИ не получает.

Очередь, контекст, план и журнал действий сохраняются в `DATA_DIR/tasks.sqlite3`. После перезапуска работа продолжается с сохранённого шага. Подтверждённая отправка файла не повторяется; если соединение оборвалось в момент отправки и результат неизвестен, задача просит проверить чат. Если итоговое уведомление не удалось подтвердить, результат всё равно можно запросить фразой «Статус задачи 3».

Один фоновый исполнитель работает параллельно обычной переписке. Пределы: три активные задачи на собеседника, 20 на аккаунт, 15 новых задач за сутки на собеседника; до 16 запросов модели и 32 различных действий на задачу, до 20 минут непрерывного выполнения за один запуск. Задачи расходуют API-запросы отдельно от обычных ответов. Приложение должно работать постоянно; после простоя просроченное поручение запускается при возобновлении сервиса.

«Не отвечай мне» приостанавливает также фоновые поручения этого собеседника; «Давай продолжим» разрешает продолжение. Очистка памяти останавливает и удаляет его задачи вместе с сохранённым контекстом. Личный архив владельца сохраняется. На Railway база задач, как и остальная память, требует постоянного Volume `/data`.

## Личный архив всех переписок

**Каждый собеседник — отдельный диалог.** Архив охватывает все доступные личные переписки подключённого аккаунта: входящие, исходящие вручную и ответы помощника, а также сообщения от ботов и «Избранное». Группы и каналы не импортируются. Фильтры ответов ИИ, пауза и его квоты не отключают архивирование.

При запуске архив догружает доступную старую историю по каждому личному диалогу и продолжает с сохранённой позиции после перезапуска. Новые сообщения сохраняются независимо от фонового импорта. Фото, видео, видеокружки, голосовые, музыка и произвольные файлы скачиваются в исходном виде из Telegram, без дополнительного сжатия. Лимит анализа ИИ в 20 МБ/3 минуты к архиву не применяется. У загрузок есть сохраняемая очередь и повторные попытки; статус недоступного или недокачанного оригинала отображается в просмотрщике. Кнопка «Обновить историю» запускает догрузку и повторяет неудачные загрузки.

В `data/archive.sqlite3` находятся диалоги, сообщения, направления, даты, подписи, ответы, группировка альбомов, метаданные и сведения об оригиналах. Сами файлы находятся в `data/archive-media/<dialog_id>/`; это позволяет хранить большие видео без помещения гигабайтных блоков внутрь SQLite. Для резервной копии сохраняйте **весь каталог DATA_DIR**, остановив приложение или используя согласованный снимок volume. Копия только SQLite не содержит оригиналов.

Веб-просмотр: список диалогов, поиск по имени/тексту и внутри выбранного диалога, сообщения по порядку, воспроизведение аудио/видео/кружков, просмотр фото и скачивание файлов. Входящие слева, исходящие справа. Русский поиск нечувствителен к регистру. Если формат не воспроизводится браузером, оригинал можно скачать. Правки сохраняют предыдущий текст; полученные уведомления об удалении помечают запись, сохраняя уже скачанный оригинал.

Локальный запуск просмотра не требует входа в Telegram: задайте `ARCHIVE_PASSWORD` в `.env` и запустите `archive.ps1`, затем откройте `http://127.0.0.1:8080`. В текущей локальной установке пароль уже создан и сохранён в исключённом из Git `data/archive-access.txt`. Когда запущен `run`, просмотр поднимается автоматически при заданном пароле. На Railway он доступен через HTTPS-домен и тот же пароль. Пустой `ARCHIVE_PASSWORD` отключает веб-доступ, но не запись архива.

Память ИИ и личный архив — разные хранилища. Фраза «Забудь нашу переписку» очищает контекст ИИ, его резюме и рабочие копии вложений, **но не удаляет личный архив владельца**. ИИ не получает доступ к перепискам с другими людьми. Веб-просмотр не позволяет отправлять сообщения от аккаунта.

Полнота ограничена тем, что Telegram ещё позволяет получить: удалённые до импорта сообщения, недоступные/истёкшие вложения и секретные чаты восстановить нельзя. Уведомления о правках/удалениях во время отключения могут не прийти; архив не является точной копией всех последующих удалений в Telegram. Заполненное хранилище и сетевые ошибки будут видны в статусе загрузок. Уже сохранённые сообщения автоматически не удаляются.

## Установка заново

Проверенная среда: Windows x64, Python 3.11, FFmpeg и ffprobe в PATH. Зависимости закреплены в `uv.lock`.

```powershell
uv sync --frozen --extra dev --extra audio --extra calls
# Только если .env ещё нет:
Copy-Item .env.example .env
```

Без `uv`:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev,audio,calls]"
```

Второй вариант использует диапазоны версий из `pyproject.toml`, а `uv sync --frozen` — точные версии из lock-файла. Для текста, документов и фото достаточно `uv sync`; `audio` добавляет локальное распознавание, `calls` — экспериментальный голосовой транспорт. FFmpeg устанавливается отдельно; на этой машине он уже доступен.

## Что делает юзербот

Для девушки не нужны технические команды. Можно писать как в обычной переписке, присылать фото и голосовые, сказать «Отвечай голосом», «Пиши текстом», «Что ты умеешь?», «Нарисуй котика», «Не отвечай мне» или «Давай продолжим». Фраза «Забудь нашу переписку» очищает сохранённую память, но не удаляет сообщения из самого Telegram. Эти фразы обрабатываются приложением напрямую; настройки аккаунта и ключей выполняются владельцем один раз. Подсказки в чате написаны простыми словами, технические причины ошибок остаются в локальном журнале.

ИИ отвечает только на **новые входящие личные сообщения**. Не отправляет рассылки, не отвечает в группах/каналах, на исходящие сообщения, сообщения от Telegram-ботов и служебного аккаунта Telegram. Импортированная история не вызывает автоответов. По умолчанию отвечает любому обычному аккаунту, который напишет первым. `ALLOWED_USER_IDS=123,456` ограничивает ответы указанными ID; пустое значение разрешает все входящие личные чаты. Эти ограничения не распространяются на личный архив владельца.

Ответы идут без служебной подписи и повторного представления. В обычной беседе помощник отвечает коротко и тепло, не рекламирует свои возможности; по прямому вопросу честно сообщает, что он ИИ. Длинные тире в обычном тексте заменяются дефисами, код и оформленные цитаты сохраняются. Claude должен различать факты, слова собеседника, мнения и гипотезы, аргументированно возражать ошибочным утверждениям и не менять позицию ради одобрения. Адаптация касается явно выраженных предпочтений языка, тона, длины и объяснений. Она не создаёт скрытого психологического профиля. Эти инструкции действуют и в голосовом режиме.

Поддерживаются **жирный**, *курсив*, зачёркивание `~~текст~~`, заголовки, ссылки, нумерованные/вложенные списки, галочки `- [ ]` / `- [x]`, цитаты, строчный код и блоки кода с указанием языка. `||спойлер||` скрывает текст до нажатия. Markdown-таблицы превращаются в подписанные строки, удобные для телефона. Картинки в Markdown не скачиваются автоматически: их подпись становится ссылкой и не теряется; генерация `/image` по-прежнему отправляет настоящий файл.

Длинные ответы делятся с сохранением Telegram entities, границ Unicode и лимита числа выделений. Код не получает недопустимых пересечений с другими стилями. Если Telegram отклоняет оформление, отправляется читаемый текстовый вариант; спойлер при этом заменяется пометкой, а не раскрывается. Озвучка убирает Markdown, не читает блоки кода и скрытые спойлеры. HTML из ответа не исполняется. Модели явно предложено использовать оформление умеренно, чтобы ответы было удобно читать на телефоне. Правила Telegram entities сверены с [официальной документацией](https://core.telegram.org/api/entities).

Команды собеседника:

| Команда | Действие |
| --- | --- |
| `/ai_help` | Возможности и ограничения |
| `/ai_stop` | Отключить автоответы этому собеседнику |
| `/ai_start` | Возобновить автоответы |
| `/ai_reset` | Удалить его архив, оригиналы вложений, резюме, индекс поиска и предпочтение озвучки |
| `/ai_recall слова` | Найти до четырёх релевантных фрагментов его исходной переписки |
| `/ai_voice_on` / `/ai_voice_off` | Включить/отключить озвучку для этого диалога |
| `/image описание` | Создать картинку; также распознаются «Нарисуй …», «Сгенерируй картинку …» |

Генерация выполняется только при явном запросе: одна PNG, качество `low`, запрошенный размер 1024×1024. Провайдер в проверке вернул **1254×1254**, поэтому фактические размеры могут отличаться. Результат отправляется вложенной картинкой в Telegram и сохраняется в архиве. Редактирование переданного изображения пока не реализовано. Подмена модели запрещена; если API её отклонит, пользователь получит ошибку.

## Голос как действие агента

Агент знает доступность Fish Audio и текущий режим конкретного собеседника. Через `set_reply_mode` он сохраняет выбор «голос с текстовой копией» или «только текст», через `send_voice` передаёт подготовленную реплику в Fish и отправляет полученный OGG/Opus в текущий Telegram-чат. Составная просьба «Можешь отвечать голосом и рассказать короткий стих» включает режим и озвучивает сам стих. Разовая просьба «Прочитай это один раз» не меняет постоянную настройку. Точные короткие команды переключения по-прежнему работают без модельного запроса.

Для выразительности в аргументе озвучки допустимы `[chuckle]`, `[long pause]`, `[short pause]`, `[pause]`, `[sigh]`, `[whisper]`, `[warm tone]`, `[excited]`, `[emphasis]`. Модель выбирает их по смыслу, без постоянного смеха и лишних пауз. В текстовую копию эти пометки не попадают. Поддержка inline-тегов описана в [официальном материале Fish Audio](https://fish.audio/ar/blog/fish-audio-s2-fine-grained-ai-voice-control-at-the-word-level/?articleLocale=en); точная интонация зависит от модели и выбранного голоса.

На один обычный ответ допускается одна озвучка через инструмент, до 1500 символов. Повторный вызов не отправляет второй файл, автоматическая озвучка не дублирует результат инструмента. При сбое Fish сохраняется текстовый ответ; при неизвестном результате отправки автоматического повтора нет. Правка или удаление исходной реплики до завершения синтеза отменяет отправку. Голосовые инструменты доступны в обычном диалоге; фоновые задачи пока сохраняют прежний набор инструментов.

## Память

Исходные входящие тексты, подготовленные сообщения/ответы и загруженные оригиналы вложений сохраняются локально до явного `/ai_reset`. Новая версия не удаляет старые пары сообщений при переполнении контекста. Архив занимает диск и со временем растёт. Переписка до первого запуска и сообщения, отброшенные из-за полной очереди или фильтров, в архив не попадают. Вложения отклонённых по лимиту запросов не скачиваются.

По умолчанию модель получает до **24 последних пар** подробно, с бюджетом до **100 000 символов** с учётом нового запроса. До 16 изображений и 8 МБ сериализованного содержимого на свежую часть; при превышении бюджета старые изображения заменяются текстовой пометкой, а оригиналы остаются локально. Поиск по архиву возвращает текст, не пересылает старые картинки автоматически.

Суммаризация начинается после 32 пар, когда за пределами свежего контекста накопилось минимум 8 новых пар, либо раньше при накоплении 40 000 символов старого текста. За один запрос обновляется один блок старой переписки примерно до 60 000 символов. Резюме допускает до 18 000 символов и хранит отдельно слова пользователя, предпочтения, решения, задачи, исправления, гипотезы ассистента и неопределённость, с указанием источника. Пороги настраиваются через `MEMORY_*` в `.env.example`.

Перед ответом выполняется поиск по словам текущего запроса только в рабочей истории этого собеседника; добавляются релевантные фрагменты и часть ещё не обобщённых старых сообщений. Агент также может вызвать `search_memory`, чтобы найти прежние сведения по уточнённому запросу. Свежие исправления имеют приоритет. При ошибке резюмирования прежняя память и исходный архив сохраняются. **Это не абсолютная память:** поиск лексический, резюме может упустить детали; `/ai_recall` помогает уточнить исходные формулировки. Суммаризация является дополнительным запросом к Claude и учитывается отдельно.

### Карточка собеседника

Кроме свежей переписки и резюме, в `history.db` хранится отдельная карточка каждого собеседника: явно сообщённые имя, фамилия, обращение, возраст или полная дата рождения, город, занятие, предпочтения, близкие, проекты и планы. Факт содержит исходную цитату, номер сообщения, дату, статус и связь с предыдущей версией. Профили не смешиваются между чатами. Фоновый агент тоже получает актуальные факты перед каждым шагом.

Новые сообщения, принятые в обработку ИИ, разбираются отдельным фоновым запросом. Пересланные сообщения, вымышленные персонажи и данные третьих лиц не должны становиться профилем собеседника. Очередь сохраняется при перезапуске; ошибки повторяются с паузой пять минут, максимум три попытки. Запоздавший результат не перезаписывает более свежий факт. Расход на эти запросы включён в статистику, число запросов карточек показано отдельно. Старый личный архив не импортируется автоматически в карточки.

Явное исправление заменяет прежнюю версию; несогласованные утверждения получают отметку противоречия. Возраст хранится с датой сообщения и не увеличивается наугад. Текущий возраст рассчитывается только из полной даты рождения; противоречие с названным возрастом требует уточнения. Планы помечаются как потенциально устаревшие через 30 дней, проекты, отношения, город и занятие через 180 дней. Это срок перепроверки, а не автоматическое удаление или выполнение поручения.

Сведения из собственных голосовых заметок поступают как неподтверждённые, чтобы ошибка распознавания не заменила верный профиль. Их можно проверить и подтвердить текстом. Чужие пересланные голосовые и обычные аудиофайлы в карточку не извлекаются.

| Фраза в личном чате | Результат |
| --- | --- |
| «Покажи память» / «Что ты помнишь обо мне?» / `/my_memory` | Свои сохранённые факты, номера, даты, неопределённость и очередь |
| «Забудь мой возраст» (также имя, фамилию, дату рождения, город) | Отозвать конкретное поле |
| «Забудь факт 12» / `/forget 12` | Забыть свой факт и версии этого поля |
| «Подтверди факт 12» / `/confirm 12` | Подтвердить своё сведение из голосового |
| «Обнови память» / `/memory_retry` | Повторить ранее неудачные разборы |

При выборочном забывании удаляются версии выбранного поля и сбрасывается сводка. **Чтобы значение не вернулось из пересказа, старая рабочая переписка целиком исключается из дальнейшего контекста и поиска ИИ.** Остальные отдельные факты сохраняются, кроме сведений из того же исходного сообщения. Старые незавершённые разборы и фоновые задачи этого чата отменяются. Новая переписка снова пополняет контекст. Забытое поле можно сохранить заново явной фразой «Запомни: …». Оригиналы личного архива владельца остаются. Удаление или правка исходного сообщения отзывает зависимые факты без восстановления старой версии.

В защищённом веб-архиве откройте диалог и нажмите **Память ИИ**: доступны значения, даты, статусы и исходные цитаты. Это просмотр для владельца; управление своей памятью собеседник выполняет в Telegram. Извлечение основано на модели и проверке цитат, а не гарантированном понимании каждого текста.

`/ai_reset` не меняет согласие/отказ от автоответов и счётчики ограничений, но удаляет содержательную память и адаптационные данные. Уже отправленные Telegram-сообщения и данные на стороне API-провайдеров эта команда не удаляет.

## Вложения и точные ограничения

| --- | --- |
| Фото | JPEG, PNG, WebP; до 20 мегапикселей; перед моделью уменьшаются до 1280 px по большей стороне, EXIF-ориентация учитывается |
| Текст | UTF-8: TXT, MD, CSV, TSV, JSON, XML, YAML/YML, PY, JS, TS, HTML, CSS, LOG; максимум 40 000 символов извлечённого текста, обрезка объявляется |
| PDF | До 100 первых страниц; только извлекаемый текст, без OCR/иллюстраций; зашифрованные PDF отклоняются; сканы лучше прислать фотографиями |

| Excel XLSX | Первые 8 листов, 1000 строк и 30 столбцов, общий предел текста 40000 символов; формулы как текст, без графиков; до 30 МБ после распаковки |
| Видео | MP4, MOV, MKV, WebM, AVI, M4V при поддержке кодека FFmpeg; до 180 секунд и 16 мегапикселей; выборка примерно одного кадра на 10 секунд, максимум 12 кадров с метками времени |

Любое входящее вложение — **до 20 000 000 байт**. Это лимит приложения, а не лимит MTProto. Неподдерживаемые XLS, PPT/PPTX, ZIP/RAR, EXE, GIF-анимации и другие форматы отклоняются с объяснением. Анимированный WebP также отклоняется; используйте видео. Видео анализируется по отдельным кадрам: быстрые события могут быть пропущены. Если звук не обработан, это явно указывается. Распознавание речи может ошибаться.

На этой машине установлены `faster-whisper` и локальная модель `base`, распознавание включено. При новой установке первое использование скачивает модель; затем она работает локально на CPU. Парсеры запускаются отдельными процессами с таймаутом 120 с, при распознавании — 300 с. Это ограничение времени, а не полноценная песочница ОС. Скачивание вложения ограничено 90 с.

## Fish Audio

`FISH_API_KEY` используется только для `https://api.fish.audio/v1/tts`; ключ A6 туда не передаётся. Выбраны `FISH_MODEL=s2.1-pro-free` и голос `41d6b093e3014fb097a0b3eb1749247c`. `FISH_SPEED` — 0.5–2.0, по умолчанию 0.7 для голосовых сообщений и звонков. Модель и голос не подменяются при ошибке.

`VOICE_REPLIES=auto`: озвучка ответов на голосовые или после включения режима собеседником. `always`: озвучка по умолчанию во всех диалогах (собеседник может отключить её). `off`: глобально только текст. При вызове `send_voice` сначала отправляется голосовое, затем текстовая копия без тегов; при ошибке синтеза остаётся текст. Если модель не вызвала инструмент, прежняя автоматическая озвучка в выбранном голосовом режиме остаётся запасным вариантом. Её текст ограничен 1500 символами, о сокращении говорится явно, блоки кода остаются в тексте. Fish возвращает MP3, FFmpeg преобразует его в OGG/Opus для Telegram. Таймаут TTS составляет 60 с на весь запрос, максимум 10 МБ результата.

## Входящие звонки и их архив

Приём приватных Telegram P2P-звонков использует `py-tgcalls==3.0.0` и `ntgcalls==3.0.2`. Включение:

```dotenv
ENABLE_CALLS=true
ENABLE_TRANSCRIPTION=true
CALL_ALLOWED_USERNAMES=yyunachiu
FAST_MODEL_NAME=gemini-3.8-flash
FISH_SPEED=0.7
```

Можно также задать числовые `CALL_ALLOWED_USER_IDS`. Имена разрешаются при запуске; неизвестное имя не открывает доступ остальным. Одновременно принимается один звонок, до 10 минут и 120 реплик. Фраза ограничена 20 секундами; примерно 600 мс тишины завершают её. Повторная речь останавливает текущую обработку и озвучку. Два периода молчания по 45 секунд завершают разговор. `/ai_stop` действует и на звонок. Микрофон и динамики сервера не используются; исходящие `phone.RequestCall`, видео- и групповые звонки не поддерживаются.

Gemini получает аудиофразу и возвращает расшифровку, ответ и намерение. Через 3 секунды запускается резервный путь: локальный Whisper и Sonnet; первый успешный результат используется, второй запрос отменяется. После ошибки Gemini на 2 минуты включается только резерв. Отмена не гарантирует отсутствие списания у провайдера. Прокси A6 возвращает для запрошенного `gemini-3.8-flash` известный идентификатор `gemini-3.8-flash-n`, который явно разрешён; другие подмены отклоняются. Видеосообщения анализируются Gemini по выборке кадров и локальной расшифровке. При его ошибке исходные кадры остаются для Sonnet. Это не непрерывное понимание всех событий видео.

Поручения из звонка сохраняются в очередь Sonnet, результат приходит в переписку. Можно спросить состояние задач или запросить поиск в интернете. В комплекте 34 заранее озвученных клипа со скоростью 0.7. Во время ожидания используются нейтральные реакции с интервалом не менее 12 секунд; подтверждение задачи возможно только после её сохранения. Длинная задержка API всё равно остаётся заметной: в живой проверке резерв завершил распознавание и формирование ответа примерно за 18 секунд, до финального синтеза. Скорость естественного разговора пока не подтверждена.

Начальное приветствие сообщает о сохранении разговора. Аудио обеих сторон, распознанные реплики, прерванные ответы, длительность и причина завершения сохраняются отдельно для каждого собеседника. Откройте диалог в веб-архиве и нажмите **Звонки**, чтобы прослушать или скачать OGG. После сбоя незавершённый PCM восстанавливается при старте. Запись остаётся на постоянном томе `/data/call-recordings`, даже после очистки памяти ИИ. Расшифровка содержит только успешно распознанные фразы; при ошибке остаётся исходное записанное аудио. Пропущенные вызовы хранятся с известной причиной; ИИ не должен выдумывать личную занятость. Звонок, прошедший целиком во время отключения приложения, может иметь лишь служебную запись Telegram, без аудио.

База и файлы на постоянном томе являются основным архивом. Отдельная Telegram-группа для резервного хранения пока не создаётся. Реальное установление звонка и двусторонний звук требуют проверки с разрешённого аккаунта; автоматические тесты используют имитацию транспорта.

## Ограничение автоответов и хранение

Два тяжёлых запроса одновременно, остальные сохраняются в очереди. Для переписки: до 6 собранных реплик за 10 минут и 30 за час на собеседника, до 200 за сутки на аккаунт. Десятисекундного запрета для соседних сообщений больше нет. У звонков отдельные ограничения: один активный разговор, до 10 минут и 120 реплик, до 6 попыток приёма в минуту на собеседника. При исчерпании квоты реплики ожидают её освобождения в базе. Состояние доступно владельцу через /queue; это не гарантия немедленного ответа при большой очереди. Переключение голоса и помощь имеют отдельный лимит 6 действий в минуту и не мешают сразу задать вопрос. `/ai_stop` и очистка памяти действуют независимо от квоты; подтверждение очистки может быть пропущено при исчерпанном лимите управляющих действий. Ограничения Telegram FloodWait соблюдаются. Это прикладные ограничения, они не гарантируют отсутствие ограничений со стороны Telegram.

`.env`, сессии Telegram, база, вложения, демо и виртуальные окружения исключены из Git. `.env` и `data/telegram.session` дают доступ к API/аккаунту; храните их локально. Обработанный текст/фото отправляются A6, текст для озвучки — Fish Audio. Оригиналы документов и видео остаются в архиве; извлечённые кадры и текст передаются моделям. Аудиофразы звонка передаются A6 для Gemini, а в резервном пути распознаются локально; полученный текст передаётся Sonnet. Провайдеры могут иметь собственные правила хранения данных.

Совместимость A6 подтверждена реальными запросами, а не только документацией исходных моделей.


## Статистика владельца и расходы

В **Избранном подключённого Telegram-аккаунта** доступны `/admin`, `/stats` (сегодня, UTC+05:00), `/stats all` и `/memory`. В других чатах эти команды не предоставляют административный доступ. В веб-архиве после входа кнопка **Расходы** показывает ту же статистику и состояние памяти.

Учёт сохраняется в `/data/metrics.sqlite3` и начинается с установки обновления. Каждый ответ API учитывается отдельно, включая шаги инструментов, фоновые задачи и суммаризацию. В статистике есть входные и выходные токены, чтение и запись кэша, созданные изображения и озвучки, отправленные файлы и геолокации, поиск и сохранённые сжатия. Отсутствующие поля usage показаны как «нет данных», а не нули. Текущий A6 при живой проверке возвращает чтение кэша, но не запись.

Заданные владельцем тарифы: Claude Sonnet 5.5, за миллион токенов: обычный вход $0.36, выход $1.80, чтение кэша $0.036, запись $0.45. Изображение $0.0012. Кэш не прибавляется к входным токенам повторно. В отчёте отдельно показаны известная часть расходов и оценка, в которой неизвестное чтение/запись кэша приняты за ноль. Стоимость озвучки не задана; запросы без usage не получают выдуманную цену. Это расчёт по указанным тарифам, не сверка с балансом провайдера. Исторические расходы до обновления не восстанавливаются.

Сжатие обрабатывает ограниченные порции архива, оставляет свежую переписку и подбирает старые детали поиском. Новые исправления, ограничения, числа и незавершённые задачи имеют приоритет. Сводка обновляется пакетами, без отдельного платного сжатия на каждую реплику. При ошибке предыдущая сводка сохраняется, повтор откладывается на пять минут. Чаты изолированы; сжатие одного не блокирует сжатие другого. Стабильные инструкции модели не меняются вместе с текущей минутой, что позволяет провайдеру переиспользовать префикс; факт кэширования определяется только usage.

## Удаления и изменения сообщений

**Удаление в Telegram не удаляет запись из личного архива.** Текст, уже скачанные оригиналы и прошлые версии текста остаются доступны владельцу, с отметками об удалении и изменении. Если вложение удалили до загрузки, получить его из Telegram может быть уже невозможно. События, которые Telegram не доставил (например, во время простоя), нельзя гарантированно обнаружить.

В рабочей памяти ИИ изменённая реплика заменяется актуальным текстом, удалённая получает отметку, а зависимое резюме перестраивается. Ответ на старую версию не отправляется, если изменение обнаружено до отправки. Текущие фоновые задачи этого диалога консервативно отменяются: их сохранённый контекст мог содержать старое поручение. Уже отправленные результаты не отзываются; другие диалоги не затрагиваются. Личный архив хранится отдельно от рабочей памяти ИИ.


## Прочтение, короткие реплики и восстановление ответа

При начале обработки входящих сообщений юзербот отправляет Telegram отметку прочтения. Для голосового или видеокружка отметка прослушивания отправляется только после получения результата распознавания. Неудавшаяся загрузка или ошибка разбора не помечает звук прослушанным. Архивирование само по себе не читает все диалоги за владельца.

Короткие соседние текстовые сообщения собираются после паузы 1.2 секунды, не дольше 4 секунд первоначального ожидания. В одной реплике до 12 сообщений и 4000 символов. Текст длиннее 1000 символов, вложение, команда или явный ответ на другое сообщение обрабатываются отдельно. Пока модель ещё думает и не началось действие, новая короткая фраза в течение первых 8 секунд может перезапустить подготовку общего ответа, не более двух раз. Это может повторно расходовать токены отменённого запроса. Если действие или отправка уже начались, новая реплика остаётся отдельной; Telegram-ответ привязан к её сообщению. Лимит считается на собранную реплику, а не на каждое слово.

`history.sqlite3` хранит очередь, подготовленный контекст, готовый текст, ответы модели и результаты инструментов. Незавершённая реплика восстанавливается после запуска. Готовая озвучка сохраняется на томе в `reply-media`, файлы инструментов повторно используются. Подтверждённые действия не запускаются заново. До отправки исходящий Telegram-запрос сохраняется с его random_id; повтор после обрыва использует тот же запрос. Если Telegram сообщает о повторном ID, но не возвращает подтверждение, либо восстановленное содержимое отличается, статус становится «Нужна проверка отправки», без нового ID и слепого дублирования.

В Избранном владельца `/queue` показывает незавершённые ответы и случаи неопределённой доставки. В веб-разделе «Расходы» также есть счётчики очереди. Подтверждённо завершённые задания сохраняют компактную запись о своих исходных сообщениях; тяжёлые служебные данные удаляются. Личный архив переписки остаётся независимым.

Во время обычного деплоя выполняется догрузка входящих сообщений с последней отметки работы, с запасом в минуту, максимум за последние сутки. Уже учтённые сообщения не отвечаются повторно; исходящие, боты и служебные сообщения исключены. При первой установке этой версии старая переписка не получает автоматических ответов. Удалённое до восстановления сообщение не воссоздаётся из догадок; сохранённый личный архив остаётся. Потерю базы или постоянного тома такая очередь компенсировать не может. Если процесс погиб до сохранения результата платного API, запрос к нему может потребоваться повторить.
